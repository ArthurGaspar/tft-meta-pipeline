# Architecture

## Components

| Component | Location | Language | Role |
| --- | --- | --- | --- |
| Static data | `simulator/static_data.py`, `data/` | Python | Extracts Set 18 snapshots per patch from Community Dragon |
| Lobby simulator | `simulator/simulate.py`, `simulator/patches.py` | Python | Plays lobbies with a hidden meta, writes Riot-shaped match files |
| minicloud | `minicloud/` | Python | Local S3/Lambda/SQS/EventBridge-style platform, driven by `infra/stack.yaml` |
| ETL functions | `functions/` | Python | Validate → Load → Aggregate, deployed onto minicloud |
| Database | `sql/schema.sql` | SQL | MariaDB 10.6+ locally (`localdb.py`), MySQL 8 in CI |
| Orchestrator | `run.py` | Python | Deploys the stack, runs everything, exports and grades results |
| Website | `web/` | React + TypeScript (Vite) | Dashboard and the browser combat simulator |

## One run, end to end

`python run.py [--matches N] [--seed S] [--out web/public/data]` does, in order:

1. **Load the template** `infra/stack.yaml` (resolving `${env:…}` and `${Resource.attr}` references) and validate it.
2. **Reset state**: delete `.cloud/` and `DROP TABLE` every table in `run.py:TABLES`.
3. **Deploy**: create buckets and queues under `.cloud/`, apply `sql/schema.sql`, register functions, write `.cloud/state.json`.
4. **Simulate** into `.work/` (deleted first): `raw/patch=<p>/batch-NNNN.ndjson`, plus `truth.json` (hidden values) and `game.json` (browser sim data).
5. **Upload** every raw file to the `tft-raw` bucket. Each put queues an S3-style event for matching triggers; nothing runs yet.
6. **`cloud.drain()`**: Validate runs per raw file, its writes to `tft-staged` queue Load, Load writes MySQL. Failures retry, then dead-letter.
7. **`cloud.tick(minutes=60)` + `drain()`**: the simulated clock fires the hourly schedule, Aggregate reads MySQL and writes `site/*.json` to `tft-public`.
8. **Export**: copy `tft-public/site/*` into `--out`, then write `pipeline.json` (invocations, cost estimate, quarantine reasons), `truth-check.json` (grading), and copy `.work/game.json`.

Functions run **sequentially in one process**; there is no concurrency.

## Where files live

| Path | Contents | Committed? |
| --- | --- | --- |
| `data/set18/<patch>.json` | One immutable snapshot per patch | yes |
| `data/set18.json` | Latest snapshot + `patches` map (client version → patch) | yes |
| `.work/` | Simulator output for the last run | no |
| `.cloud/s3/<bucket>/…` | Bucket objects; metadata sidecars in `<bucket>/.meta/` | no |
| `.cloud/logs/<Function>/…` | Lambda-style log streams | no |
| `.cloud/queues/<queue>/*.json` | Dead-letter messages | no |
| `.cloud/state.json` | Deployed stack state | no |
| `.db/data/` | Private MariaDB data directory | no |
| `web/public/data/*.json` | Dashboard data (regenerated by CI on deploy) | no |

## The hidden-truth boundary

The project's central claim is that the rankings are checked against values the pipeline never saw. The boundary is enforced by structure, not by a runtime guard:

```
                 hidden side                         │            pipeline side
 simulator: Meta powers, economy plans,             │   raw NDJSON (Riot match-API shape only)
 positioning skill, Riot change → power shifts      │        │
        │                                            │   Validate → Load → Aggregate
        ├─► .work/truth.json ──────────┐             │        │
        └─► .work/game.json ──┐        │             │   tierlists.json, patch-changes.json, …
                              │        ▼             │        │
                              │   run.py truth_check ◄────────┘
                              ▼        │
                     web combat sim    └─► truth-check.json
```

- Functions in `functions/` receive only S3 events, bucket objects, `STATIC_DATA` (public game data), and the database.
- Everything the pipeline labels (comp, carry, playstyle, contest) is **inferred from the final board**, like a real analyst would.
- `game.json` carries hidden powers on purpose: the combat sim plays with the same balance as the lobbies. It is not an input to the ETL.

Keep it this way when adding features: if a new statistic needs a hidden value, it belongs in `truth_check`, not in Aggregate.

## AWS mapping

minicloud uses AWS shapes so the functions would port with small changes:

| Template type | AWS analogue | In this stack |
| --- | --- | --- |
| `bucket` | S3 | `tft-raw`, `tft-staged`, `tft-quarantine`, `tft-public` |
| `function` | Lambda | `Validate`, `Load`, `Aggregate` |
| `trigger` | S3 event notification | `RawUploaded` (`raw/*.ndjson` → Validate), `Staged` (`*.ndjson` → Load) |
| `schedule` | EventBridge rule | `Hourly` (`rate(1 hour)` → Aggregate) |
| `queue` | SQS dead-letter queue | `tft-failed-events` |
| `database` | RDS for MySQL | `MetaDb` |

This is an emulator for a portfolio project, not an AWS deployment; see [minicloud](minicloud.md#what-it-does-not-model).
